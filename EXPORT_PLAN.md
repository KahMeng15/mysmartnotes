## Export (PDF & DOCX) with Templates

**TL;DR**
- **Summary:** Add a per-user template system + UI to choose format/template in the note view, wire server-side generators (ReportLab for PDF, `python-docx` for DOCX), run generation as a background task with WebSocket progress, register a provided Instrument Sans font, and store/serve generated files from existing static mounts. Reuse the existing `DocumentGenerator` and follow existing router/task patterns.

---

## Steps

### Data Model & Schema
- **Template model:** Add `Template` to `app/models/db.py` storing `user_id`, `name`, `config` (JSON for page size/orientation/margins/columns/styles), `created_at`.
- **Pydantic models:** Add template CRUD and export request schemas to `app/schemas/schemas.py` (fields: `format`, `template_id`, `include_images`, `toc`, etc).

### Template Management UI & Router
- **UI page:** Add `app/static/templates.html` (or reuse existing layout).
- **Client JS:** Add `app/static/js/templates.js` to create/list/edit/delete templates.
- **Router:** Add `app/routers/templates.py` following existing router patterns (auth + `db` dependency) and register it in `main.py`.

### Note UI: Export Modal
- **Export button:** Update `note.html` to add an Export button that opens a modal.
- **Modal options:** Format (PDF / DOCX), template selector (user templates), toggles (TOC, cover page, math rendering).
- **Submit behavior:** POST to an export endpoint with `format`, `template_id`, and options; show a task id/spinner immediately.

### Server: Integrate Generator & Background Task
- **Endpoint:** Extend existing `lectures` generation endpoint or add `/lectures/{id}/export` to accept `format` and `template_id`. Validate template ownership.
- **Background:** Enqueue generation via `app/utils/tasks.TaskManager.submit_task` and return the task id immediately.
- **Worker wrapper:**
  - Fetch lecture content as structured `ContentSegment`s from `app/processing/text_processor.py`.
  - Apply template config to the generator.
  - For PDF: call `app/processing/document_generator.DocumentGenerator.generate_pdf(...)` (extend to accept template options and custom fonts).
  - For DOCX: add `app/processing/docx_generator.py` to map `ContentSegment` → `python-docx` styles and write to `generated/{lecture_id}/OUTPUT.docx`.
  - Save generated file paths to `Lecture.output_pdf_path` or create a `GeneratedDocument` record and commit.

### Fonts & Assets
- **Fonts dir:** Add `app/static/fonts/` and accept/bundle the Instrument Sans TTF.
- **ReportLab:** Register the font via `pdfmetrics.registerFont(TTFont(...))`.
- **python-docx:** Configure styles to reference the TTF for DOCX output.
- **Fallback:** If Instrument Sans is missing, fall back to a configured substitute and document the behavior.

### Images & Math
- **Images:** Ensure images referenced in `ContentSegment`s use paths under `output/` or `generated/` (these are static-mounted), and embed them into both PDF and DOCX outputs.
- **Math rendering (optional):** Render LaTeX to images server-side (MathJax-node or similar) and embed image outputs into exports.

### Progress & UX
- **WebSocket progress:** Use `app/utils/websocket.py` manager to push progress updates from the background task to the logged-in user.
- **Frontend:** In `note.html` show progress, provide final download link, and optionally an “email file” action.

### Download Endpoint & Static Serving
- **Storage path:** Save generated files to `generated/{lecture_id}/`.
- **Serving:** Use the existing static mounts (configured in `main.py`) so generated files are directly downloadable.
- **Lecture record:** Update `Lecture.output_pdf_path` (or the new generated document record) with the generated file path.

### Requirements & Tests
- **Dependencies:** Add `python-docx` to `requirements.txt`.
- **Tests:** Add pytest(s) to:
  - POST an export request.
  - Wait for task completion (poll or WebSocket).
  - GET the download and assert correct `Content-Type` and non-zero file size.

### Documentation & Sample Template
- **UI help text:** Document template options and export features in the UI.
- **Sample template:** Provide a sample template that sets:
  - Page size and orientation
  - Two-column option
  - Instrument Sans for body and headings
  - Heading/paragraph/list styles (alignment, color, background, weight, size)
  - Page numbers and footer text: "Generated by mysmartnotes.vercel.app | Create notes and study smart! | {Date and time generated}"

## Verification

### Manual
- Start server and login.
- Create a template at `/templates`.
- Open a note at `/note/{id}` → Export → choose format/template → trigger export.
- Observe WebSocket progress, then download generated PDF/DOCX and verify fonts, headings, images, TOC, cover, and footer.

### Automated
- Add pytest that calls the export endpoint, waits for generation completion via task status or WebSocket, then requests the download and asserts non-empty file content and correct MIME type.

## Decisions
- **PDF engine:** Use ReportLab (`app/processing/document_generator.py`).
- **DOCX engine:** Use `python-docx` (new `app/processing/docx_generator.py`).
- **Execution:** Run generation as a background task with WebSocket progress updates.
- **Templates:** Per-user templates only.
- **Fonts:** Instrument Sans will be bundled (TTF/OTF); fallback configured if absent.
